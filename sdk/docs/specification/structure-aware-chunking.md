## Scope and proposal inventory

## Primary external research and dependency decisions

Context7 skill was read, but no Context7 tools were exposed in this session; official sources were fetched directly. Research here identifies contract constraints; T02/T06 must document their selected pinned parser/algorithm behavior before implementation.

* [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) defines block and inline parsing, including fences, Setext headings and HTML blocks. Tables require an explicit extension rather than an assumption that they are CommonMark.
* [markdown-it-py usage](https://markdown-it-py.readthedocs.io/en/latest/using.html) documents selectable parsing presets and table rules. It is a candidate AST frontend already installed transitively, not yet a declared direct dependency. A production import requires an explicit appropriate extra/dependency.
* [reStructuredText specification](https://docutils.sourceforge.io/docs/ref/rst/restructuredtext.html) defines adornment hierarchy, nested structures, field/definition lists, literal blocks, references and grid/simple tables. A heading-only regex does not meet the required normalization surface.
* [Docutils configuration](https://docutils.sourceforge.io/docs/user/config.html) exposes file insertion and raw-content controls. RST normalization must not execute `include`, fetch URLs, load local files, or execute unknown directives. Preserve unsupported directive source as raw content with diagnostics; test this behavior.
* [Docling chunking](https://docling-project.github.io/docling/concepts/chunking/) separates native structural chunking and contextualization. Retain the SDK's native Docling path and supported custom chunkers rather than flattening every format.
* [LangChain experimental source](https://raw.githubusercontent.com/langchain-ai/langchain-experimental/main/libs/experimental/langchain_experimental/text_splitter.py) computes adjacent cosine distances between buffered sentence embeddings. It offers percentile, standard deviation, interquartile and gradient thresholds and a requested chunk count. Its joining serialization does not itself prove original whitespace fidelity; the SDK variant must slice original source offsets. T06 must research zero vectors, degenerate thresholds and numerical behavior instead of delegating correctness blindly.

Base dependencies cover SQLAlchemy/asyncpg/alembic/httpx/ULIDs. Extras cover html, chunkers, openai, milvus, model2vec, docling, serving, geoip, dynamic, logging and datasets. Python floor is 3.13. Avoid a new LangChain-experimental dependency unless T06 establishes a concrete benefit over an SDK-native algorithm; existing Embedder must remain injectable. Optional extras must fail clearly at construction/use and must not break core imports.

## Normalization and extension contract (T02)

Add a normalized representation alongside Document, not as a replacement transport. A normalized document identifies its original Document, source format, original string, ordered root nodes, retained coverage units, exclusions and diagnostics. Nodes carry deterministic id, kind, content, ordered children, parent_id, heading level/title when applicable, source spans and JSON-compatible metadata. Kinds include document, section, heading, paragraph, list, list_item, code_block, table, table_row, blockquote, admonition, image, figure, caption, horizontal_rule and raw_block.

Spans are half-open Python Unicode character offsets `[start_offset, end_offset)` into the exact `Document.content` passed to normalization, never UTF-8 bytes or offsets into fetched HTML before an ingestion parser transformed it. Preserve CRLF coordinates through any newline normalization. Multiple disjoint spans are supported; a merged chunk must not claim a fabricated continuous source interval. Container spans and retained leaf units are distinct so coverage does not double-count nested nodes. Heading context, repeated headers, added fences and overlap are synthetic/repeated provenance, not new retained source.

Format parsers normalize independently of packing. Publish an instance registry/protocol with normalize(Document) and a stable nonsecret configuration identity. Built-in format routing supports explicit MARKDOWN/RST/HTML and conservative plain text; missing format remains TEXT for legacy Documents. Never guess raw HTML from an originating PDF/HTML media type when the parser produced Markdown. Plugin registration is per instance, deterministic, included in cache identity, and documents duplicate/unknown-format behavior; no global mutable registration is required.

Markdown dialect: CommonMark headings, code, nested lists, quotes, links/images, rules and raw HTML, plus explicitly enabled pipe-table support. Embedded HTML is normalized or preserved as raw content; never discarded. RST: heading styles in document encounter order, overline/underline distinctions, literals/code, nested/definition/field lists, admonitions, grid/simple tables, roles/references, directives. Unsupported constructs retain raw source with diagnostics. HTML: h1-h6 hierarchy through section/article/layout containers, paragraph/inline text, lists, tables with row/header/caption and available span attributes, pre/code, quotes, figures/captions, links/entities; malformed input recovers with retained text or explicit raw fallback.

Do not execute markup. HTML script/style removal is an explicit default exclusion with spans/reasons; nav/header/footer/aside removal is configurable and recorded. Do not equate layout divs with semantic sections. Hidden-content policy must be explicit and preserve documentation tabs by default where extractable, consistent with existing ingestion behavior. Preserve Unicode, inline link text/destination, alt/caption text and code indentation. Prose whitespace/entity normalization is documented and traceable. Malformed or unsupported input may diagnose/fallback; silent loss is forbidden.

### T02 concrete normalization API (2026-10-09)

Public package `fastrag.normalization` exposes `SourceSpan`, `NormalizedNode`, `CoverageUnit`, `Exclusion`, `Diagnostic`, `NormalizedDocument`, `Normalizer`, `NormalizerRegistry` and four adapters. `NormalizedDocument.document` holds the original transport; `source` is its unchanged string; `roots` contain section hierarchy; `walk()` traverses preorder. Nodes contain concatenated exact retained source slices as `content` (HTML retains markup; excluded spans are removed even from containers), plus semantic `title`, `level` and JSON metadata. `spans` may therefore be disjoint after explicit HTML exclusions. Inline interpretation lives in metadata, so link destinations and code syntax are never rewritten away. Unicode CRLF line maps are computed from the original string. Section spans cover descendants; leaf/container spans can overlap. Coverage units partition original source independently at structural boundaries, including syntax and whitespace. Exclusions are the only permitted gaps. Consumers must use unit intervals, not treat node spans as disjoint coverage. Units identify their most specific covering node; original slices remain authoritative during serialization.

Node IDs are SHA256 of `normalization-v1:{document.id}:{ordinal}:{kind}:{start}:{end}`. Heading hierarchy uses a stack, attaching jumps to nearest preceding lower level. Duplicate headings get distinct IDs. Registry routes only `metadata.content_format` (default text), rejects duplicates unless `replace=True`, rejects unknown formats, and exposes deterministic sorted adapter identities without constructing unselected optional adapters. Native Docling is deliberately unsupported by this registry and retains its existing path.

`MarkdownNormalizer` uses markdown-it-py CommonMark plus table rule, keeping original block slices, inline token metadata and nested structure. Embedded HTML is a raw block. `RstNormalizer` uses the Docutils parser directly with no writer/transforms, disables file insertion/raw directives, and invokes an instance-local allowlist of known built-in directive classes, bypassing process-global custom directive callbacks. Docutils line/rawsource locations are mapped to original lines; locations missing from the parser are explicitly diagnosed and conservatively inherited, not represented as exact cell offsets. Unsupported/error directive source remains raw. HTML uses stdlib `HTMLParser(convert_charrefs=False)` with original positions, balanced recovery for common omitted paragraph/list/cell endings and EOF. Layout tags flatten rather than become sections; headings define hierarchy. It preserves inline markup and extracts links/images/cell spans into metadata. Script/style are excluded by default; optional boilerplate exclusion is configured via tag names. Hidden markup is retained by default (including documentation tabs); optional hidden exclusion is explicit. HTML entities remain original in content and decode in semantic titles/metadata.

RST source-boundary repair (T02A): Docutils `CodeBlock.run()` can assign a literal node the parser's **ending** line, so `node.line` is not an authoritative block start. Capture directive entry and consumed-block bounds in the instance-local directive state, using original line offsets for LF/CRLF. Rebind Docutils explicit construct dispatch and nested state-machine classes/cache per parse, so the allowlist and bounds apply inside sections, lists and admonitions as well. Heading spans contain only title/adornment lines; they never extend to the next body node. Directive nodes own the original directive/options/body block, while ordinary literal nodes own original indented/quoted lines. Trim separator blank lines from these precise blocks; whitespace remains retained coverage. Unsupported, disabled raw/include, and failed/empty directives become one raw source block with parser diagnostics, rather than several overlapping diagnostic body nodes. Exact sibling blocks must not overlap; conservative table/cell/container provenance remains explicitly diagnosed. Never search the entire document for repeated code/title text to repair a parser hint. Regression acceptance includes exact heading/code/following paragraph slices, repeated bodies, adjacent and nested directives/literals, empty sections/directives, malformed/unknown/raw directives and CRLF. Research: [Docutils state source](https://docutils.sourceforge.io/docutils/parsers/rst/states.py) shows `run_directive` consumes the indented block before calling a directive; [RST specification](https://docutils.sourceforge.io/docs/ref/rst/restructuredtext.html) defines adornments, literal indentation and directive block termination. This refines A04/T02 source fidelity; packing remains T03B.

Direct optional extra `normalization` declares markdown-it-py and Docutils; adapters import lazily with actionable extra-install errors. HTML/text adapters require no additional dependency. Context7 skill applied, but no tools available; official [markdown-it documentation](https://markdown-it-py.readthedocs.io/en/latest/using.html), [Docutils configuration](https://docutils.sourceforge.io/docs/user/config.html), and [HTMLParser](https://docs.python.org/3/library/html.parser.html) were used as fallback.

## Structural engine and token contract (T03)

`StructureAwareChunker` extends existing Chunker, with normalizers injected separately. Pure split consumes normalized nodes; async refinement uses asplit. Default configuration: target_tokens=400, max_tokens=600, min_preferred_tokens=100, overlap_tokens=0, max_overlap_tokens=50, merge_small_sections=True, allow_cross_top_level_merge=False, preserve_heading_hierarchy/code_blocks/table_rows/list_hierarchy=True, include_heading_path_in_embedding=True, semantic_mode="heuristic", oversized_block_policy="split_with_context". Validate integral bounds, `0 < minimum <= target <= maximum`, and `0 <= overlap <= maximum_overlap` at construction. Every output-changing option and normalizer/tokenizer identity affects config_hash.

A tokenizer protocol provides deterministic count and safe lossless split boundaries, plus stable identity. T03 must specify concrete default tokenization and dependency extra. If a model tokenizer is unavailable, publish an explicitly named conservative fallback; do not report character or whitespace counts as model tokens. Budgets guarantee the configured tokenizer only; embedding-model compatibility requires matching tokenization. Count exact serialized embedding input, including heading paths, serialization delimiters, repeated table headers/fences/captions/parent-list labels and overlap. No additive assumption: tokenization may be nonadditive. Record content and embedding counts separately.

Meaningful sections fitting the hard limit remain whole even above target. Headings with no body supply hierarchy only, and heading-only/empty documents return no content chunks. Heading-level jumps attach to the nearest preceding lower level; duplicate titles remain distinct section IDs. Unheaded prose belongs to the document root. Top-level heading changes start new groups by default.

Deterministic merge policy: first pack adjacent compatible blocks within a section; only adjacent small sibling sections sharing a parent may merge, preserving original child headings/order, without crossing top-level boundaries or exceeding the exact embedding budget. Related means shared structural parent, not an implicit topic classifier. A run of eligible tiny siblings packs in source order; stop before a non-small/incompatible sibling. Unmergeable small chunks are valid. Merged metadata identifies the nearest common ancestor and all source section IDs. T03 must specify tie-breaking and trailing-fragment rebalancing in tests before implementation.

Oversized sections split by subsection, block, paragraph, sentence, logical sub-block, then safe lossless character/token boundary. Prefer target without splitting fitting sections solely for size. Never discard a long sentence or trailing text. Code stays whole if fitting; otherwise use available function/class boundaries, then logical lines, retain language/fences/indentation and mark fragments when syntactic integrity cannot be guaranteed. Tables split at complete rows with caption/schema/header repeated and counted; preserve cell contents, multiline cells and exposed rowspan/colspan relationships. Lists split at top-level items, keeping nested descendants with parents; split oversized item internals with repeated parent context recorded.

Two explicit policies: `split_with_context` obeys the hard budget and flags loss of atomic structure when unavoidable; `preserve_and_flag` may emit an oversized atomic block, recording overflow and reason. If heading/context or an indivisible serialization cannot fit even the smallest retained unit, raise a clear ChunkingError or use the explicit overflow policy; never loop, silently truncate or silently omit heading context. T03 must pin single oversized table-row/cell/code-line and deeply nested list behavior.

Overlap applies only to continuous prose split within the same section. Prefer complete sentences that fit configured overlap; use none when no complete sentence fits. No cross-section overlap, table-row overlap or arbitrary code duplication. Account for overlap in exact final budget and record source ranges of repeated content. Overlap does not fill otherwise small chunks.

## Output, fidelity, embedding and parent context (T04)

Output remains Document. `Document.id` is chunk_id, `metadata.document_id` and reserved parent_id reference the parsed parent Document, `metadata.position` mirrors reserved chunk_index. Add parent_section_id, heading_path, heading_levels, source_section_ids, chunk_type, token_count, embedding_token_count, source_format, source_spans, split_reason and overlap/repeated-context provenance. Keep compatibility `headings` where useful for existing loggers. Metadata uses JSON primitives; no AST/model/vector/entire parent document embedded in every chunk.

Generic chunkers retain base ID formula `content_hash(parent_document_id + ':' + index + ':' + content)`; structural IDs use the versioned T04 formula below to distinguish context/provenance/configuration. IDs are stable across identical Document IDs/content/configuration and deterministic boundaries. Formatting/content edits and insertion changing parsed IDs or chunk positions may change IDs; no edit-stability promise. Config_hash distinguishes cache entries even if unchanged chunk text produces the same chunk ID. Normalized section/node IDs derive from document identity and structural occurrence/source coordinates, not heading title alone. Publish exact algorithm/version.

Embedding input is independently testable heading path plus serialized chunk content, with headings not duplicated when already represented. Keep readable citation/display content unchanged. The embedding pipeline must actually use this builder; merely testing a helper does not satisfy integration. Embedding input selection/version affects embedder cache identity, preserving old content-only defaults for ordinary Documents. Stored/query context still exposes readable content, not a replacement consisting solely of embedding decoration.

Database-independent parent context resolves document/section IDs to ordered normalized section contents through a public in-memory index/protocol. Test merged ancestor expansion, correct document resolution and missing-parent behavior. Do not force Milvus or another database for this API, and do not repeat entire parent content in every chunk.

Every operation validates retained coverage, order, lineage, sequential positions, heading paths, repeat provenance and hard budgets/flagged overflow. Validate normalized unit references plus slice intervals, including fallback-split ranges; listing a node ID alone does not prove all of its text was retained. Report exclusions separately. Never use naive concatenation equality after intentional serialization changes. Diagnostics report chunk sizes/counts, small/oversized frequency, merges/splits/fallbacks, model calls and duration; timing must not affect deterministic metadata/IDs or packing. Cache replay must preserve substantive diagnostics and metadata.

## Optional chat refinement (T05)

Defaults never call an LLM. `disabled` disables refinement; `heuristic` is deterministic local structural/sentence refinement; `llm` requires explicitly injected ChatModel and an affirmative external-transmission option before sending source text. Refiner proposes offsets/node boundaries only, never rewritten text. Validate structured JSON, ordered unique integer boundaries, bounds/alignment, coverage and resulting budgets before applying. Refine eligible prose within structural constraints rather than allowing models to reorder sections or split rows.

Model/endpoint configuration stays in existing provider. Add timeout, retry/backoff, bounded concurrency and optional cache with nonsecret model/config/content keys. Malformed responses, timeout and provider errors deterministically fall back to structural splitting; retain original content and record fallback reasons/call counts. Test no-call defaults/denied transmission, cancellation, retry ceilings, cache hits, reproducibility of fallback and failure isolation across documents. Existing SemanticChunker chat API remains compatible; any behavior change is documented and tested rather than silently reinterpreting character chunk_size as tokens.

### T05 accepted refinement contract (before implementation)

`ChatBoundaryRefiner` is a separate existing-ChatModel strategy. Requires `allow_external_transmission=True` and caller-defined nonsecret endpoint/model/settings `identity`; provider credentials/URLs are never introspected. Options bound finite timeout, retries/backoff/concurrency, request character size and optional in-memory LRU success cache. Provider errors/timeouts retry; invalid responses fall back immediately. Cancellation propagates through invocation, semaphore waits and backoff. Only validated successful proposals cache; keys hash configuration, exact text, node ID and allowed offsets. Failures never poison later requests/documents.

`StructureAwareChunker(semantic_mode="llm", semantic_refiner=...)` requires this strategy. Synchronous splitting raises before transmission; async `asplit`/`asplit_normalized` refine before ordinary deterministic packing/serialization/validation. Other modes never invoke an injected strategy. Only plain leaf paragraphs in Markdown/RST are eligible: no inline markup, HTML, lists, tables, code, directives or section crossings. Sentence-end candidates must align with tokenizer and rendered atoms. Oversized requests use heuristics. Response JSON must be exactly `{"boundaries": [offset, ...]}`: strictly increasing unique interior Unicode integers chosen from supplied candidates; empty means unchanged packing. No generated text is accepted. Valid cuts subdivide authoritative atoms before exact budget packing; original lineage/maps/coverage remain validated. Failure uses the same heuristic output independently per paragraph. Diagnostics report calls/cache hits/fallback codes externally, without modifying chunk IDs. Nonsecret strategy configuration affects output/cache identity. Legacy `SemanticChunker(llm=...)` is unchanged.

## Embedding semantic boundaries (T06)

`EmbeddingSemanticChunker(embeddings=Embedder, buffer_size=1, breakpoint_threshold_type="percentile", breakpoint_threshold_amount=None, number_of_chunks=None, sentence_split_regex=r"(?<=[.?!])\s+", min_chunk_size=None, add_start_index=False, batch_size=64, cache=None, policy=None)` is independent of structural/chat refinement. Legacy `SemanticChunker(llm=...)` remains unchanged. No new EmbeddingModel/provider dependency is added. Async `asplit` and pipeline evaluation call the supplied SDK `Embedder.embed`; sync split raises before any call. Provider construction explicitly controls transmission. Its opaque config hash, model ID and declared dimension enter cache identity; raw credentials/endpoint do not enter chunker config.

Research: [official upstream source](https://github.com/langchain-ai/langchain-experimental/blob/main/libs/experimental/langchain_experimental/text_splitter.py), inspected 2026-10-09, uses neighboring sentence embeddings, cosine distances and strictly-above statistical cuts. Defaults mirror upstream: percentile 95, standard_deviation 3, interquartile 1.5, gradient 95. Percentiles use linear interpolation; standard deviation uses population variance; interquartile uses mean + amount*(Q75-Q25). Gradient uses forward/backward endpoint and centered interior distance differences. Two-sentence gradient returns one unchanged chunk (upstream returns two sentences without embedding); other two-sentence threshold modes embed but have no above-threshold cut.

Regex must compile and have no capturing groups or zero-width matches. Match starts become source offsets; separators belong to the following sentence. Blank edge segments merge with their neighbor. Embedding windows are exact source slices with up to buffer_size neighbors on either side. All output is contiguous original slicing, preserving whitespace/order in direct and pipeline output, unlike upstream sentence joining. add_start_index emits exact Unicode start_index/end_index. Empty/blank input emits nothing; a single sentence bypasses embedding. Consecutive batches contain at most batch_size windows. This is plain sentence processing, not syntax-aware parsing or a hard token budget; T07 owns format gating.

Intentional upstream differences: number_of_chunks selects the strongest min(requested-1, available) cosine-distance cuts exactly; earlier offset wins ties. It takes precedence over threshold selection, replacing upstream's approximate interpolated-percentile count. min_chunk_size measures original Unicode characters: suppress cuts producing short fragments, then merge a short tail backward. It may reduce requested count; a document shorter than minimum stays whole. Equal scores without requested count produce no cuts. Zero vectors raise ChunkingError (cosine is undefined), as do wrong vector counts, nonnumeric/bool/nonfinite values, inconsistent/wrong declared dimensions. The [upstream cosine helper](https://github.com/langchain-ai/langchain-community/blob/main/libs/community/langchain_community/utils/math.py) maps NaN/infinite NumPy similarities to zero; SDK deliberately rejects invalid vectors instead. Scale-normalized cosine avoids overflow/underflow and clamps roundoff. Provider errors/cancellation propagate unchanged for inherited Policy handling; no silent fallback.

Integer options reject bool (buffer >=0; batch/count/minimum >=1). Threshold amounts must be finite numbers; percentile/gradient in [0,100], other multipliers >=0. Unknown modes/malformed regex raise ConfigurationError. Zero-width matches detected against actual source also raise before embedding. Algorithm version and every effective option/provider identity enter config. Fake Embedder tests establish exact topic cuts, statistical rules, fidelity, numerical/config errors, provider failures and cache replay/identity. The resolved-output hook verifies contiguous integer chunk indices and restores source order before events/yields when a cache backend replays by ID.

## Parser/chunker capability safety (T07)

Declare accepted output formats at chunker boundaries, extensible for custom formats. Validate each emitted Document at runtime; static type hints aid discoverability but cannot establish a mixed source's dynamic outputs. Backward-compatible custom chunkers without declarations retain a documented legacy permissive contract; built-ins enforce known capabilities. Unsupported format errors name document/source, actual format, receiving component and supported alternatives. Follow existing Policy raise/skip events without concealing failures; on_error=raise is used in validation.

ParserRouter must not decode unknown binary PDF/ZIP as generic text. Known text MIME/extensions route appropriately; explicit user route/default takes precedence. Capability errors distinguish unsupported format from malformed content/missing dependencies. Native Docling remains serialized tree + DoclingChunker; Markdown Docling output routes to text structural chunking. Test mixed MIME sources and a custom parser producing multiple Document formats from one Source, extension registration, unsupported types and explicit routes without forcing all output to Markdown.

### T03 pinned engine contract (2026-10-09, before implementation)

The default tokenizer is `TiktokenTokenizer("cl100k_base")`, declared directly in the `normalization` extra. It counts `encode_ordinary` of the exact final text, so literal special-token strings are ordinary document content. `Utf8ByteTokenizer` is an explicitly selected conservative byte-count fallback requiring no dependencies; it is not a model-token estimate. Injectable `Tokenizer` supplies nonempty stable `identity`, `count(text)` and `boundaries(text)` (ordered Unicode character offsets including 0 and len). Counts need not be additive or monotonic. Candidate serialized outputs are measured individually; split boundaries never decode partial BPE bytes. Encoding resources may need tiktoken's first-use cache/download; the byte fallback provides a fully offline option. Primary API research: [tiktoken README/core](https://github.com/openai/tiktoken).

`split_normalized` is the format-independent engine entry point. Sections with direct content are separate from subsections; fitting direct sections remain whole. Ancestor headings appear in embedding context; original child headings remain readable display. Small, unsplit, adjacent sibling sections merge greedily left-to-right up to target, stopping at non-small sections; a final small remainder remains intact (no reverse redistribution). Top-level merges require the explicit option. Oversized sections pack adjacent blocks greedily to target, allowing a single fitting block above target. No redistribution across structural boundaries.

Markdown/RST display retains readable original syntax; HTML serializes tag events as Markdown-like headings, lists, rows, code and links with decoded entities. Serialization is independent of authoritative source syntax. Every serialized atom records exact source intervals and output coordinates; removed layout delimiters remain `syntax` provenance. Split fragments reference only their retained slice intervals, never whole node IDs as a proxy for coverage. Coverage-unit intersections are exposed as `retained_intervals` with unit/node IDs, roles and display coordinates. `serialization_map` records text/source transformations. `repeated_context` distinguishes source-backed table headers/list parent labels/overlap from generated fences. Only unrendered hierarchy/whitespace/layout source is attached as explicit hierarchy/syntax provenance to the nearest chunk; non-whitespace body gaps are serialized in source order under the T03B refinement below. Heading-only documents emit no chunks and are classified as hierarchy-only by later validation.

Code fragments use language fences counted in full, prefer function/class starts then complete logical lines; a too-long line falls back to Unicode-safe slices with `atomic_structure_lost`. Tables prefer complete source rows and repeat headers and captions, with parser cell/span metadata preserved. A too-long row is split with the same header context and flagged; no fictitious cell offsets are inferred for conservative RST spans. Lists prefer complete top-level items and preserve nested items; an oversized item uses line/sentence boundaries and repeats the first parent label with explicit repeated provenance. `preserve_and_flag` emits over-budget atomic blocks intact and records overflow; impossible mandatory context under split policy raises `ChunkingError`. Prose overlap is a suffix of complete terminated sentences from the immediately preceding fragment of the same paragraph/section, capped and individually budget checked; no overlap for separate blocks, code, table or list pieces.

For T04 integration `build_embedding_text(content, metadata)` is versioned and pure, uses the same builder the engine budgets, and stores no entire parent document. T04 must route actual embedding calls through it, add parent-context resolution and independently validate coverage/serialization maps rather than trusting recorded counts.

## T08D schema-local index naming and compatibility

Cache indexes use `ix_<table_name>_<column_name>` without a schema prefix. All current identifiers are ASCII, bounded below PostgreSQL's 63-byte limit, unique among table/index/primary-key relations within either cache or chat metadata, and stable across schema names. Chat expiry indexes use the same rule; its explicit composite indexes, enums and other constraint names already omit schema prefixes and remain unchanged. This removes SQLAlchemy's four-hex-digit truncated-name collision risk rather than adding another truncated hash. Research: [SQLAlchemy naming and truncation](https://docs.sqlalchemy.org/en/20/core/constraints.html#truncation-of-long-names) and [PostgreSQL CREATE INDEX](https://www.postgresql.org/docs/current/sql-createindex.html) specify deterministic truncation and schema-local index relation names.

Existing cache indexes retain their names and data. Readiness and index installation recognize an existing valid, ready, nonpartial single-key B-tree index on the required table/column, independent of name; partial/expression indexes do not satisfy this contract. Missing coverage gets the stable new name under the existing schema advisory lock. The startup readiness check stays one database round trip; repeated/fresh opens must not add duplicate indexes or rerun payload migration solely because names changed. Existing snapshot/source upgrades, bucket semantics, vectors, metadata, empties and garbage collection remain unchanged. A conflicting unrelated relation occupying a canonical index name must not be silently accepted as coverage.

Acceptance: deterministic compilation of the exact failing schema and generated 63-byte ASCII/multibyte schemas, relation-name uniqueness and schema-independent stable names; isolated actual PostgreSQL exact-schema create/reopen with source/document/empty-bucket persistence; legacy-name readiness, missing-index repair without data loss or duplicate coverage; relevant cache tests and full isolated suite (T09 failures tracked separately). This supports A11 cache compatibility and the T08 reliability gate; no destructive index rename/drop or data migration is introduced by this repair.

### T09F — explicit API embedding width (2026-10-09)

`OpenAIEmbedder(dimensions=N)` requires a positive integer (excluding bool) and
passes that explicit value to LangChain's `OpenAIEmbeddings(dimensions=N)`;
its actual OpenAI-compatible request therefore requests N dimensions. `None`
continues to infer known model widths without sending a dimensions field, which
preserves older models such as ada-002. Explicit settings require provider/model
support; unsupported requests propagate as nontransient `EmbeddingError` for
4xx responses, never silently retry without dimensions or truncate/pad vectors.
Every direct `embed` call validates one returned vector per input and every
vector's width against the declared `dimension`, including inferred widths.
Mismatches raise actionable nontransient `EmbeddingError` before indexing/querying.
Provider extras retain their existing JSON override semantics; a dimensions
extra that contradicts the declared contract consequently fails shape validation.
Model IDs remain unchanged. Explicit configurations add
`dimensions_request_version=1` to config/cache identity to invalidate embeddings
produced before the request fix. Inferred configurations retain their identity.
Resolved output validates cached vectors too, hydrating projected headers when
needed, before emitting events or yielding downstream. Existing collections
created by the old omission must be reviewed/rebuilt in a new owned collection
when their vectors were produced at a different width; no automatic store
migration or deletion occurs.

AgrospAI fetching and querying share `FASTRAG_EMBEDDING_DIMENSIONS` through
`config_from_env()`. Unset uses 4096; set must parse as a positive integer.
Fetching's `--embedding-dimensions` overrides that valid environment default.
The same width must be used for fetching and same-collection querying.

Research: [LangChain OpenAIEmbeddings reference](https://reference.langchain.com/python/langchain-openai/embeddings/base/OpenAIEmbeddings)
identifies `dimensions` as a client parameter supported by OpenAI embedding-3
and later models. Installed `_invocation_params` explicitly forwards it only
when non-None. Compatible providers decide their own model support.
